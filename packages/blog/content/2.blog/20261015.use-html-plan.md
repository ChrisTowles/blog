Today I asked Claude Code to plan the first interactive lesson for [Farwonder](https://learn.farwonder.app): Patrick Winston's MIT talk [_How to Speak_](https://ocw.mit.edu/courses/res-tll-005-how-to-speak-january-iap-2018/), word for word in his own voice, stopping now and then so the learner can do something. I didn't get the usual wall of markdown. I got a page I could read in a minute and answer in place.

That page comes from [html-plan](https://github.com/anthropics/claude-plugins-community), a skill by Thariq Shihipar in Anthropic's community plugin marketplace. It's the best planning tool I've used with an agent, and I want everyone using it.

```text
/plugin marketplace add anthropics/claude-plugins-community
/plugin install html-plan@claude-community
```

Then put `/html-plan` in front of anything that touches more than a couple of files: `/html-plan add send later to the composer`.

## What makes it different

**The closed tree is the summary.** A plan is a tree of claims, and each level answers one question. Level 1 says what someone can now do or see. Level 2 says how it works. Level 3 says where, as a `file:line`. With everything closed you read only the level-1 claims, and together they tell the whole change. There's no TL;DR, because the tree already is one.

**Every claim has to prove itself.** Each claim gets exactly one exhibit: a UI mockup, a state machine with the screen for each state, a call tree, a schema in the project's own language, or real code. Code that exists is pulled from the repo with real line numbers. Code that doesn't exist yet is labeled as a sketch. You can't hide a vague idea behind a nice paragraph.

**Decisions sit on the claim they change.** It's not a list of open questions at the end. Each decision is a small form with a suggested answer already picked, and some show what follows from a choice ("then this claim goes"). A button at the bottom counts what you haven't opened ("5 to answer") and takes you to the next one.

**You answer in the page.** Pick options, edit a schema, strike a call you don't want, comment on any claim or any line. **Respond** turns all of it into one markdown answer, which you paste back to Claude. The skill tells Claude not to build anything until that answer arrives.

**It's written to be read.** All the prose is in Simplified Technical English: short sentences, active voice, one word for one thing. A linter (`pack.mjs`) checks the tree's shape and the word budget, fills in the real code, and inlines everything into one file that works offline. With Claude's Artifacts it's a private link, ready to share.

Compare that with how I used to review plans: scroll a long markdown answer in the terminal, skim it, type "looks good", and find the decision I missed when the PR showed up. Here the decisions come to me, each with a default I can accept in one click, and the agent waits for my answer.

## The two it made for me today

- **[How to Speak Lesson Plan](https://claude.ai/artifact/LtQMCbqE1r6TBa6b52xrZT)**: five claims and five decisions. The talk plays one chapter at a time with the words lighting up as he says them, stops for the learner, records each source's licence, and connects to a rendering engine my brother is building. It flagged things like an hour of audio being too much to decode into memory at once, and the licence needing a record on every activity.
- **[WorkOS Sign-In Plan](https://claude.ai/artifact/MLt6BN62BwwY551tx1vSHp)**: grown-up sign-in for Farwonder, with five decisions.

That's the whole pitch. Install it, type `/html-plan`, and stop approving plans you only skimmed.
